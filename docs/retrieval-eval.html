评估边界

  • 分词（tokenize.ts）、屏蔽词（isBlockedGram）、IDF 加权与相对截断（rankByOverlap）均取自真实源码并实际执行；SQL 粗召回用等价的字符串包含模拟。
  • 不含权重衰减、灵光一闪概率通道、Prompt 拼装；别名用事件自带的 alias 字段模拟（真实库是 memory_event_aliases 表），每条事件只有 1 条 gist + 1 条 summary，真实库片段更多，召回可能略高于本评估。
  • 理想命中按「真实陪伴场景下什么算恰当」人工标注，情绪类用例带有语义期待，纯字符串检索天然难以满足——这正是评估要暴露的。

结论

以下数值取自本次运行。 1. 从「不敢接」到「该接的接住」：逐例全对 48/78 → 51/78，Recall 53.6% → 82.6%；代价是精确率 90.2% → 67.9%——多认回来的典型是「加班」顺带想起面馆（那件事本来就是加班后去吃面），算误伤，不算硬错。 2. 关键不在门槛，在「拿什么去比对」：只把门槛放宽到「长句命中 1 个词」（全字段、仍两段式）停在 44/78、副作用 9 例；把比对文本收窄到「写入时抽的标签」才到 51/78、副作用 7 例。一句话印象（gist）是完整句子，「了没 / 的地 / 有点」这类虚词 bigram 一撞就误召回，summary 同理，所以都不参与比对。 3. 两条召回通道必须合并：上一版「标题命中就停」，于是「最近压力大，团子还生病了，都没好好吃饭」只想得起团子；合并后加班、团子、发烧三件都能想起来。分组变化——变差：B 短实词 6/7 → 5/7、I 边界 3/4 → 2/4、L 否定转折 4/4 → 1/4、N 硬干扰 2/3 → 0/3、Q 近邻混淆 6/7 → 5/7；变好：C 换说法 4/7 → 7/7、D 情绪 2/5 → 3/5、F 身份名 1/3 → 2/3、H 时间 1/3 → 2/3、K 错别字 1/5 → 2/5、M 问句指代 1/5 → 4/5、O 长尾抽样 0/3 → 1/3。 4. 剩下 27 条是机制与人的差距清单：否定句（「不是吃面，是火锅」「不是加班，是去唱K」）挡不住；硬干扰（「我妈公司楼下的面馆」撞上拉面/咖啡店）指的是别家；近邻挑不净（「妈妈的体检」也勾出自己的体检报告，gist/标题里的「周三」「朋友圈」「想去」这类字面照样撞）；纯情绪（「今天好累」）没有任何字面线索；Top3 注入上限——一次说四件事只给三条，跨段合并后第 4 件仍进不来；单字兜底只扫前 8 个字，句尾的「猫粮」够不着；英文同义词（overtime / coffee）没有对应标签，数字不参与分词（「38.5度」）；噪音 bigram（「跳槽的念头」里的「槽的」）会抬高相对截断线，把该召回的挤下去。 5. 情绪倾诉组 2/5 → 3/5：纯字符串检索无法从「累」联想到「加班」，属架构层面的差距，不是调参能补的。 6. 编辑距离兜底：评估后决定不转正。四道闸（独立成词、同位置换一字、唯一候选、拼音差 ≤1 字）确实能零误报捞回「拉铁↔拿铁」51/78，但四道闸缺一不可——去掉「独立成词」闸，时序剧情里「看到一只→到期」「越来越大了→大理」的噪音 bigram 立刻误报；去掉拼音闸，「拉铁」分不清拿铁和拉面。能安全生效的场景只剩「用户单独打出两字错字」这一种，收益配不上复杂度与拼音依赖，留档备查、等语义层（命中后模型复核）整体覆盖。
