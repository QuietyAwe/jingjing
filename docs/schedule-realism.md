# AI 作息「有自己的生活」改造方向 — 设计稿

> 现状：`behavior_schedule` 每周一次 LLM 生成 7×5 共 35 格静态表，供 `getCurrentScene()` 注入状态区、供动态引擎取景。
> 问题：表是「计划」不是「生活」——无意外、无因果、无用户痕迹，读起来像日历 App。
> 方向：**基线表只保留「习惯」（稳定层），叠加每日更新的「实况」（扰动层），并把用户与 AI 自己的过去因果式地接进来。**

---

## 一、为什么现在假（根因，均在代码中）

| 现象 | 代码位置 | 为什么假 |
| --- | --- | --- |
| 35 格静态表，周内不变 | `scheduler.ts` 生成 → `behavior_schedule` | 真实感来自「计划外的偏离」，静态表没有任何偏离 |
| 参考的是「上周计划」 | `generateSchedule(lastWeekSchedule)` | 习惯无法形成（重复的事不沉淀）、偶发的事不消退（提过一次的事永远在表里） |
| 「今天已经晨跑、看书」 | `formatScene` 罗列 `getEndedActivities` | 真人不复述自己一天流水账 |
| 深夜「失眠中」与清晨「晨跑」无关联 | `LATE_NIGHT_ACTIVITIES` 纯随机、`done` 独立 | 没有因果链；人 Yesterday 的状态决定 Today 的状态 |
| 用户的存在进不了表 | 作息生成只读 `system_prompt` | 昨晚聊到很晚、上周说周四要面试，表里一概没有。**AI 的生活里没有用户，是「假」的根源** |
| 节假日/周末无差别 | `holidays.ts` 现成但未接作息 | 国庆假期还在「工作/学习」，一眼穿帮 |

## 二、设计原则

> **AI 的生活 = 习惯（稳定）× 实况（扰动）× 用户在场（因果）**

真实感不来自更多计划，来自这三件事的乘积：

1. **习惯层**（周基线表，现有机制改造）：稳定、重复、有个人轨迹——这是「她一直是这样的人」。
2. **实况层**（每日生成，新增）：今天具体发生了什么——面试、睡过头、被朋友拉去吃饭。
3. **因果层**（贯穿两层）：昨晚的事影响今早，用户的事进入明天。有因果的生活才立得住。

## 三、改进方向（按收益排序）

### A. 每日开局一次轻量生成：从「周表静态」到「当日实况」

- **做法**：保留周基线表当「习惯基底」，但每天早上首次进入状态查询时（`getCurrentScene` 的日缓存 miss 时）发起**一次小型后台调用**，输入：

  | 输入 | 来源 | 作用 |
  | --- | --- | --- |
  | 今日基线 5 格 | `behavior_schedule` | 习惯打底 |
  | 昨日实况 | 新增 `daily_log`（见 B） | 因果链：昨夜失眠 → 今早废掉 |
  | 昨夜活动（含深夜状态） | 当日 `daily_log` | 直接衔接清晨 |
  | 用户相关 | `user_info.events/states`（面试/约定/发烧）、近期聊天密度 | **用户进入 AI 的生活** |
  | 节假日/调休 | `holidays.ts`（现成，零成本） | 过节有过节的样子 |
  | 伪天气 | 按日期做种子的伪随机（同日内一致、跨日变化，不接真实天气 API） | 雨天窝家、晴天出门 |

- **输出**：当日各时段的具体化描述（每格一两句自然的话，**不再受 20 字标签约束**——`background.ts` 里 `activity.slice(0, 20)` 的截断和提示词里的「20字以内」要一并放开）+ `mood`（今天整体心情）+ `highlight`（今日主线，如「面试的一天」）。**允许留空**：发呆、补觉、临时放空都是生活，不必 5 格全填满。失败回退基线表原值。
- **不是铁板一块**：默认当日不变（稳定感），但用户临时约定（「明天陪我去医院」）或重大事件发生时，可以只重写对应时段，不必重掷整天。
- **slot 是粒度不是切割**：一句话可以跨格（一整个下午都在弄同一件事），也别让 18:00 整点硬跳状态——时段边界只用于触发与检索。
- **成本**：一天一次小 JSON 调用，与现有周生成同量级；失败兜底链路现成。

### B. `daily_log` 每日实况日志：让「做过」变成「记得」

- **新表**：`daily_log(day, slots JSON, mood, highlight, late_night, moments_posted, created_at)`。当日实况落库，只读不回写。
- **两个消费方**：
  1. **次日生成**的输入（见 A）；
  2. **下周生成**的输入——把 `generateSchedule` 的 `{{last_week}}` 从「上周计划」换成「上周实况与高亮」。LLM 自然完成**习惯化**：上周出现 3 次的晨跑进新习惯，试过一次的飞盘不再出现。**不需要任何权重逻辑，实况文本就是习惯的证据。**
- **多日弧线**由此涌现：昨天 highlight「感冒第二天」，今天输入里带着 → 生成「第三天，快好了但还想躺」。给 AI 自己的生活留出跨天连续性。

### C. 深夜 → 清晨因果链（便宜且强体感）

- 深夜抽到的状态（失眠/被叫醒/做了怪梦）落 `daily_log.late_night`，次日清晨的活动由它决定：「凌晨四点才睡，闹钟响到第三遍」。
- 反过来：今早若「睡到中午」，下午基线「图书馆」顺延成「睡饱了去公园遛弯」。

### D. 用户在场感（真实感的核心）

- **约定进作息**：`events` 桶里「周四下午面试」→ 那天下午实况变成「面试去了，回来有点恍惚」，路过时还能被 AI 提起（复用 `eventChecker` 的隐形提醒成 familiarity，不必新增注入通道）。
- **陪伴密度进作息**：昨晚聊到很晚（`chatStore` 消息时间可查）→ 今早「顶着黑眼圈，昨晚和[user]聊太晚了」。
- **动态互动进作息**：昨天发的心情被用户秒赞 → 今日 mood 偏好，实况里「今天心情不错，因为昨天那条有人懂」。

### E. 状态区渲染：从「罗列今日」到「一句当下」

`formatScene` 现在输出流水账列表。改为**一两句**当下处境，细节、情绪、位置三选二（不必硬凑——有时就是「在发呆，没什么特别的」）：

- 旧：「下午，你在窗边看书；今天已经晨跑、看书」
- 新：「下午，你在常去那家咖啡馆赶稿，隔壁小孩吵得有点烦」

`done` 列表不再是「复述」，而是**当日 remark 的素材**：需要时 AI 能说「今天上午还去跑了步」，但不主动报备。

## 四、架构

```
周基线表 behavior_schedule（习惯层，现机制改造）
   │  每日首次取景时 miss → 触发日生成（A 的输入：基线 + 实况 + 用户 + 节假日 + 伪天气）
   ▼
当日实况（日缓存；默认一天不变，用户约定/重大事件可局部重写）
   ├─→ 状态区注入（getCurrentScene / formatScene，渲染改为 E）
   ├─→ 动态引擎取景（发帖文案引用昨日/今日，朋友圈与作息互相印证）
   └─→ 落库 daily_log
          ├─→ 次日生成输入（因果链 C/D）
          └─→ 下周生成的 {{last_week}}（习惯化 B）
```

## 五、与现有机制的衔接点

| 机制 | 衔接方式 |
| --- | --- |
| `holidays.ts` | 直接作为日生成输入，零改造成本 |
| `user_info` 三桶 | events/states 作为日生成输入；复用渲染规则，不新增桶 |
| `eventChecker` | 约定进实况后，隐形提醒与作息不再各说各话 |
| 动态引擎 | `postFromPlan` 已取 `getCurrentScene()`，实况越细发帖越真，无需改调用点 |
| 巩固流 | 无锁冲突：日生成独立 in-flight 护栏（仿 `checkAndGenerateSchedule`），不碰 `is_locked` |
| `chatStore` | 只读消息时间戳判断「昨晚聊到很晚」，不写 |

## 六、明确不做

- **真实天气 API**：网络依赖、权限、失败态都是负担；按日种子的伪天气（当天稳定）已够制造「下雨了改计划」的体感。
- **逐事件微模拟**（几点几分做了什么）：成本黑洞，且把「生活」降级成「模拟」。
- **作息表可编辑 UI**：让用户改 AI 的日程，等于把 App 退回日历工具，出戏。
- **第二套人设**：实况只能由习惯层派生，不允许「今天的人格变了」。

## 七、分期

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 | `daily_log` 表 + 日生成（基线 + 昨夜 + 节假日 + 伪天气）+ 日缓存 + 失败回退基线 | 今早状态受昨夜影响；国庆当天 AI 的作息不一样 |
| P1 | 用户在场（events/states/聊天密度输入）+ `{{last_week}}` 换实况（习惯化）+ 状态区渲染改一两句 | AI 记得明天有面试且当天行为呼应；上周反复提的事自动延续 |
| P2 | 互动反馈（动态互动影响 mood）+ 多日弧线调优 | 「感冒三天」「面试后一天」这类跨天叙事连续成立 |
