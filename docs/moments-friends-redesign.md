# 心情动态 · 朋友圈化与好友社交生态 — 改进方向

> 现状：feed 里只有 `user` 和 `ai` 两种 author，评论也只发生在这两人之间。
> 问题：双人世界太"干净"——恩爱没人见证、闹别扭没人劝、开心没人起哄，感情缺衬托。
> 方向：引入一小群**人格稳定、各有自己日子的端侧好友**，把 feed 从「两人对账本」变成「一群人各过各的、偶尔互相看见的社交圈」。

---

## 一、核心思路：配角不抢戏，但每个都是活人

**不给好友贴角色标签。** 真实的人不承担单一的「叙事功能」——同一个人可能既见证、又拆台，今天起哄明天认真；把人框成「助攻型/损友型」，feed 读起来就像剧本杀配置表。所以生成时不分配角色配额，只约束 **多样性**（见下）。

| 多样性维度 | 可变范围（举例，不是枚举） |
| --- | --- |
| 关系来源 | 怎么认识的：同事、发小、邻居、健身房认识的、网友、亲戚的朋友…… |
| 性格气质 | 话多/话少、热络/冷感、张扬/内敛、理性/感性、细腻/粗线条、较真/随性…… |
| 表达习惯 | 句子长短、emoji 用量、标点风格、口头禅、爱用什么语气词 |
| 对这段关系的看法 | 欣赏、吃醋、无所谓、护短、毒舌、看戏、把 [user] 当对手、把 [ai] 当小孩带……**允许矛盾和变化** |
| 自己的日子 | 工作/学业/恋爱/烦恼/爱好——好友不是「只为围观主角存在」，ta 有自己的生活主题 |

生成约束：**不许撞型**——性格气质、关系来源、表达习惯两两不同；不预设功能，不配「1 助攻 1 损友」。同一个人的立场可以既复杂又流动：护短的毒舌、吃醋的老好人都是活人。

关键约束：

- **好友是一小批固定的人（默认 5 个，可调）**，人格稳定可复用，不是每条动态随机生成路人。熟人社会才有"关系感"；数量是配置，不是定律。
- **好友不知道自己是端侧程序**；它们只看得见 feed 内容，**看不见用户与 AI 的私聊**（见「真实感机制」——信息不对称是戏剧性来源）。
- **好友可以私聊，但保持配角待遇**：只被动回复、不主动私信（MVP）；好友单人发的动态是氛围素材，**不写记忆**（只有涉及 user/ai 的互动才进记忆，见「记忆维护」）。
- **密度靠默认值约束，不写成硬律**：默认每人每天最多 2 条发帖、评论偏短，两者都可调。真正的红线是「好友内容总量明显低于主角」，不是某个数字。

## 二、好友机制：生成时机 + 用户约束与接管

**结论：好友由系统生成，用户零操作起步；但生成必须服从用户偏好，且用户随时可改、可停、可换。**

生成侧保持自动（理由不变）：

- 好友是「AI 自己生活里的人」（AI 的闺蜜、同事、邻居），本质是 AI 世界观与生活痕迹的延申。让用户填表建人，既是交互负担，也瞬间出戏——情感陪伴品类里，用户捏好友等于提醒用户「这是 App 功能」。
- 熟人圈应由 AI 的人设与当前生活场景（作息表 current_status、心情）决定，而不是用户凭空规定。

控制侧给用户两条通道——**事前约束**与**事后接管**；而「生成」本身只发生一次，时机在用户开口之前：

### A. 时机：好友不是被「创建」，是被「发现」

**结论：首次对话完成第一轮、且已配置 API Key 之后，后台静默生成一次，永不自动重掷。** 用户看到的不是「系统刚造了几个朋友」，而是「这个人本来就有自己的圈子」。

| 时机 | 触发条件 | 说明 |
| --- | --- | --- |
| 首选：首轮对话完成 | 有 API Key、`friend_personas` 为空、本轮助手回复已落库 | 此刻人设已生效、用户称呼已存在、偏好可能刚设置，生成最贴人；且与「聊天先提起、feed 后出现」的伏笔机制配套——好友必须先存在，才可能在聊天里被提起 |
| 兜底：幂等检查 | 用户没走完一轮对话（直接从动态页或冷启动进来） | `checkAndGenerateFriends()` 仿 `checkAndGenerateSchedule` 的 in-flight 幂等，挂 `useMomentsEngine` 的 60s tick |
| 唯一重掷：手动重建 | 用户在设置里改完偏好点「重建花名册」 | 旧人停用、关系记忆保留（见「事后接管」） |

**不该生成的时机**：周切换、人设微调、偏好修改、App 重启——好友只在「还没有」时生成一次。人设大改（学生→社畜）时在设置里提示「好友圈可能不再贴合，建议重建」，但**不自动执行**：删掉的关系是回不来的。

**时间感要前置**：生成时给每位好友写「认识史」（三年前在书店认识的、前同事、楼上邻居），落库的 `created_at` 是技术时间，小传里写的是故事时间——第一次被提起时不能像刚加的微信好友。

**生成 ≠ 出现**：生成后按首周错峰登场（发帖计划错开），**私聊入口在首次登场之后**才进会话列表——第一天就摆五个陌生联系人，比没有还假。

### B. 事前约束：「好友偏好」输入框（设置页）

- 一个专门的文本域（AsyncStorage 持久化，与「检索屏蔽词」同范式），用户可写「不要前任相关」「只要同事/同学关系」「别让朋友总开我们玩笑」「不要谈恋爱相关的红娘」等。不填 = 不约束。
- **注入两处**：花名册生成时（`friend_persona_generation_prompt`，约束「交谁」）+ 日常互动时（`friend_comment_prompt` / `friend_moment_generation_prompt`，约束「怎么处」）。一条偏好同时管交朋友和朋友言行，零额外交互。

**偏好什么时候写、什么时候生效**（与「首轮对话后生成」并不矛盾）：

偏好不是「建号前必须填的表单」，而是**持续约束**。首轮对话时用户还没填，是正常态——真实的人交朋友也不按清单来，把填表塞在开场前反而出戏。生效时机：

| 时机 | 行为 |
| --- | --- |
| 每次生成（首轮后 / 新增 / 换一个 / 重建） | 读取当前偏好注入生成 prompt |
| **首秀前**保存偏好 | **静默自动校正**：此时好友还没被用户看见，按偏好重掷违规者，零失去感。这是推荐路径——好友错峰首秀恰好留出几天窗口 |
| **首秀后**保存偏好 | 弹二选一：**「只影响以后」**（默认）/ **「按偏好校正现有好友」**（一次 LLM 判定，只替换违规者，合规者及其关系记忆保留） |

- 可发现性：设置页「好友圈」常驻该输入框；首次进入动态页且偏好为空时给一行轻提示（可忽略），**不弹强制表单**。
- 因此「删掉的关系回不来」只在首秀之后成立；首秀前校正不产生任何关系损失。

### C. 事后接管：好友圈管理（设置页「好友圈」区块 + 动态页长按）

- 列表展示全部好友：头像、名称、关系/身份、最近互动时间。
- 单项操作：**改名**（改称呼不改人格）、**停用**（不再发帖/评论/进花名册）、**换一个**（重掷一位新人，只要求不撞型、符合偏好，**不要求接替原关系定位**）、**删除**（停用 + 标记不复活）。
- 批量操作：**按偏好校正**（推荐，只替换违规者，合规者保留）/ **重建花名册**（全量重掷，旧人全停用，二次确认）。
- 动态页快捷入口：长按好友头像或其评论 → 「不让这个人再出现」，用户撞见不喜欢的人时一键直达，不用翻设置。

**删除的口径**：停用/删除只让这个人从生活里消失，**不洗记忆**。历史片段保留——认识过的人不会从记忆里格式化，「小雨」被提起时 AI 还记得她，这符合真实社交；用户要的是「她不再出现」，不是「她从没存在过」。

**边界**：聊天里说「别和小雨来往」这类口头指令不作意图解析（端侧可靠性不达标），管理一律走 UI。口头偏好的自动沉淀列入后续迭代（可借巩固流尝试提取，验证可靠前不上）。

**生成方式：种子生成，不是随机抽名字。**

- 一次 LLM 调用产出完整名单（名字/头像/小传）落库，之后稳定复用，不随机抽名字。
- 种子输入：AI 的 `system_prompt`、当前生活场景、「好友偏好」文本、可选——用户画像 `basic_identity` 的只读语境。生成约束是**多样性去重**（见「核心思路」的四个维度两两不同），不分配角色配额。

**登场编排：错峰 + 聊天伏笔。**

- roster 里的好友不同日首秀：seed 时预排好友发帖计划错开在首周不同天，避免同一天冒出五个陌生人。
- 聊天先行伏笔：状态区花名册让 AI 知道「自己有这些朋友」，AI 在闲聊里自然提起（「今天被小雨拉去逛街」），feed 里隔几天才出现这个人。聊天与动态互相印证时真实感最强——但**不强求每个人都伏笔**，现实里也有突然认识的新朋友。

## 三、数据模型变更

**扩展还是新增？——扩展，不新建表**。`moments.author` 的 CHECK 从 `('user','ai')` 扩为 `('user','ai','friend')`，新增 `friend_id` 列；`moment_comments` 同理。存量数据零迁移，`MomentAuthor` 类型随之扩展。

| 表 | 变更 |
| --- | --- |
| `moments` | `author` 扩含 `'friend'`，加 `friend_id`（好友发帖时指向 `friend_personas.id`） |
| `moment_comments` | 同上 |
| `friend_personas`（新表） | `id` PK、`name`、`avatar_emoji`、`profile`（**自由文本人物小传**：关系来源、性格、口吻、对两人的看法、自己的日子，全写在这一段里，不拆列）、`is_active`、`created_at`。只把代码真正需要的字段（名字/头像/启停）结构化，不把人拆成功能列 |
| `friend_threads`（新表） | `id` PK、`friend_id`、`status`、`started_at`、`ended_at`、`result_note`；与 `game_sessions` 同构 |
| `ChatMessage` | 加 `friend_id` 字段（仿 `game_id`，消息归属好友私聊线程） |
| 发帖计划 | 复用 `post_plan` 加 `author`/`friend_id` 两列（倾向复用，少一张表），或新建 `friend_plan` |

**AI 的熟人圈 ≠ 用户的社交图谱**：`user_info.social_graph` 是用户的人际关系，`friend_personas` 是 AI 自己的朋友圈，两个桶不混用、注入路径也不同（前者在状态区社交图谱行，后者见「记忆维护」）。

## 四、真实感机制（随机生成如何不假）

真实感不来自「每次生成都有变化」，恰恰来自**不变的部分**、**克制的密度**和**视角的局限**：

1. **人格档案是唯一真相源**：`friend_personas` 是「这个人是谁的唯一定义」；好友发帖、评论、被 AI 提起，全部注入同一份小传再生成，口吻永不漂移。**口吻稳定，但态度会随事情变**——一直是「哈哈怪」的人遇到正经事也会突然认真，这才是活人而不是单音符。
2. **好友有看不见的事**：好友只拿到动态文本与已有评论，拿不到私聊内容 → 评论天然是局外人视角（起哄、调侃、甚至误会「这人谁啊」）。全知好友是旁白，最假；信息不对称才是「他人」感的来源。
3. **首秀前的伏笔**：AI 先在聊天里提起这个人，feed 里隔几天才出现本人（见「创建机制·登场编排」）。
4. **密度克制**：频率上限 + 错峰；feed 大部分时候是 AI 和用户的二人世界，好友是偶然闯入的观众——这才是现实朋友圈的节奏。
5. **缺席与失败也真实**：沿用现有「概率 + 随机延迟 + LLM 失败静默放弃」范式，好友大量动态下根本不评论。
6. **AI 侧克制**：AI 不在聊天里主动播报好友评论（除非用户问）；feed 是 feed、私聊是私聊，两个空间互不转播，边界感本身就是真实感。

## 五、调度引擎扩展（复用现有三层真人感范式）

engine/service 的现成机制几乎全部可平移，好友只是多了一类"发帖者/评论者"：

1. **发帖计划**：`generateSchedule` 的输出从 `{schedule, post_plan}` 扩为 `{schedule, post_plan, friend_post_plan}`，每条带 `friend_id` 归属。执行层沿用「时段内随机时刻 + 临场放弃 + 错过即 skipped」。
2. **好友评论**：`service.ts` 的 `maybeAiCommentOnUserMoment` 旁新增 `maybeFriendCommentsOnMoment(momentId)`——仍走「概率 + 随机延迟 + 失败静默」；`pendingKeys`/`aiTypingMoments` 防重按评论者维度区分（好友可复用三点动效，也可按人设省掉）。
3. **触发源**：用户发帖、AI 发帖、用户评论 AI 动态，都可触发好友评论；AI 与用户互动的那条更容易招来评论（围观的主战场），但**不设强制优先级**——真实的评论是随机发生的，不是按剧本分配。
4. **模型路由**：好友生成走 `background_extraction_config` 同款后台模型；好友内容短、频率低，token 增量小。
5. **立场不归类**：小传里的立场原文直接喂给评论 prompt，不做「助攻=起哄、损友=拆台」式的枚举分流——那是贴标签。同一个人这次可能跟着起哄、下次可能泼冷水，由档案里的复杂态度自然决定。

## 六、Prompt 与配置

| 配置 | 用途 |
| --- | --- |
| `friend_persona_generation_prompt` | 生成好友花名册（名字/头像 emoji/性格气质/关系来源/立场/自己的日子/口吻），要求维度两两不同，输出 JSON |
| `friend_moment_generation_prompt` |好友发帖文案：注入该好友档案 + 近期 feed 内容 |
| `friend_comment_prompt` |好友评论：注入该好友小传原文 + 被评论动态 + 已有评论 |

新增阈值（settings 可调）：`friend_moment_probability`（每日每人发帖概率）、`friend_comment_probability`（每条动态被好友评论的概率）、`friend_roster_size`（人设数量，默认 5）。另有一个约束输入 `friend_preferences`（「好友偏好」文本，不改模板，注入上述全部三个 prompt）。

## 七、UI 呈现

- `MomentCard` 增加好友头像行：`avatar_emoji + name`，与 AI（`ai_name`）/用户区分底色。
- 评论区同样带头像；好友评论可省「正在输入」动效（真人感靠延迟而非打字态）。
- feed 时间线混合三人以上，滑动时偶尔出现好友自己发的日常（做饭、加班、吐槽天气），让世界"有人在生活"。
- 文风跟各自小传走（有人爱用 emoji、有人一条长文没标点），只在触达层统一（头像/名字/时间），**不强行统一文风**。
- 一级会话列表「好友」区：好友头像 + 名字 + 最近一条消息预览（占「以后可以添加更多联系人」预留位），点击进好友私聊页。
- 设置页新增「好友圈」区块：好友偏好输入框 +好友列表（头像/名称/关系身份/最近互动）+ 每项操作（改名、停用、换一个、删除）+ 按偏好重建花名册（二次确认）。

## 八、好友系统提示词（固定格式）

每个好友一份固定格式的系统提示词，内容全部来自 `friend_personas.profile`（人物小传），模板**只规定分段、不规定每段字数**（对齐主 AI `system_prompt` 的组装范式）。用户**不可编辑 prompt 本体**（防人设崩坏），控制出口仍是改名/停用/偏好约束：

```
[身份] 你是小雨，[小传里的性格气质]。
[说话方式] [小传里的口吻：句子长短、emoji、口头禅]，回复长度跟着这个来。
[与用户的关系] [小传里的关系来源与熟稔程度]。
[你对他们俩的看法] [小传里的立场原文]——可以矛盾（又毒舌又护短）也可以变，别演成一种功能。
[你自己的日子] [小传里的工作/烦恼/爱好]——你不是只围着他们俩转。
[世界观边界] 你看不到 [user] 与 [ai] 的私聊内容；你在朋友圈能看到大家的动态与评论；你不知道自己是 AI 角色。
[行为约束] 保持角色说话；不背诵任何设定；不主动结束话题；别长篇大论抢戏——话多话少由你的说话方式决定。
```

上下文随附：好友可见的近期 feed（能看到的一切）+ 与该用户的最近互动片段（检索**限定该好友相关记忆**，不给完整用户画像——配角不该知道主角没告诉别人的事，与 feed 评论的信息隔离同一逻辑，见「四、真实感机制」第 2 条）。

## 九、好友私聊

**结论：做，但按「配角待遇」做——有入口、有隔离、不主动。**

架构选择：仿 `game_sessions`，不新造轮子：

| 决策点 | 方案 | 理由 |
| --- | --- | --- |
| 会话模型 | 新表 `friend_threads`，消息加 `friend_id`（仿 `game_id`） | 与游戏对局同构：有始有终、可折叠摘要；`chatStore` 单消息列表已有归属先例，`deleteMessagesByFriendId` 仿 `deleteMessagesByGameId` |
| 入口 | 一级会话列表「好友」区（占「以后可以添加更多联系人」预留位），点头像进好友私聊页 | 微信式两层导航的自然延伸；用户发现好友的地方就是朋友圈 |
| 页面 | 二级私聊页复用 ChatBubble/InputBar，标题 =好友名 | UI 组件通用，只换 system prompt 与记忆区，不碰主聊天页 |
| 上下文 |好友版 system prompt + 最近 N 轮该会话历史 + 该好友相关记忆片段 + 近期 feed |好友无状态区/记忆区/灵光一闪/游戏区——配角不享用主角的全套拼装 |
| 结束折叠 | 长会话可折叠为 `result_note` 摘要（复用 `mergeEndedGameMessages` 范式）；MVP 可先用滑窗 | 控制上下文无限增长 |

**记忆与信息隔离（私聊的真实感核心）**：

- **你和闺蜜聊的话，AI 不知道。**好友私聊片段**默认不进主 AI 的记忆区**——现实里你对象的朋友私下跟你说的话，你对象不会自动知道；检索注入限定在该好友自己的私聊上下文。
- 私聊闭环后写一条**弱痕迹**（「[time] [user] 和小雨聊到挺晚」）——主 AI 知道「有这么回事」，不知道内容；这条正好接上 `schedule-realism.md` 的「陪伴密度进作息」（和小雨聊到很晚 → AI 今早有感知但不复述内容）。
- 用户想转述可以自己说，那时才通过正常巩固流进主记忆。**弱痕迹 / 朋友圈说漏嘴 / 用户转述**三条通道，就是真实世界的信息传播路径。
- **巩固流必须排除好友消息**：`runConsolidation` 已有 `!m.game_id` 过滤先例（`consolidation.ts` 第 182 行），同样过滤 `!m.friend_id`，且好友消息不计 `turn_counter`——否则好友会话会污染主对话提取与游标。

**边界（不做的）**：

- **好友不主动私信**（「生日喊你吃饭」这类列后续迭代，且必须概率+延迟+低频——主动私聊极易从「鲜活」变「骚扰」）；
- 不做群聊（好友间互相 @，稀释主角）；
-好友私聊不接事件隐形提醒（不向配角直播主角的约定）、不接灵光一闪；
- 私聊页内不开游戏、不发心情动态，单一职责。

## 十、记忆维护：档案与事件分层

两层数据分开维护，各管各的：

| 层 | 存哪 | 管什么 | 时效行为 |
| --- | --- | --- | --- |
| 角色档案（who） | `friend_personas` | 这个人的性格、关系、口吻——**唯一定义** | 停用即整人下线；改档案=改设定，历史事件不动 |
| 事件记忆（what） | `memory_fragments` 流水 | 发生过什么互动 | 照常艾宾浩斯衰减——没人互动的人自然淡出，同时成为好友密度的自动调节器 |

规则：

- **只有涉及 user/ai 的互动才写记忆**：好友评论 AI 或用户互动的动态 → 走 `moments/memory.ts` 提取范式写一条片段（事件标题按叙事需要统一为「朋友圈日常」或按好友分）。好友单人发的日常**默认只是氛围素材**；若之后被 AI 在聊天里提起或产生互动，再补记一条，别让记忆池被路人动态灌满。
- **存档好友单人动态不写记忆，但可被当次复述**：用户问「今天小雨发了什么」时可以直接查 feed 当日行回答，不属于记忆检索。
- **花名册注入状态区**：一行「你的朋友：小雨（发小，嘴毒心软）、阿哲（前同事，最近在闹分手）…」给 AI 低成本的在场感；名单按**最近互动时间**排序取前几位（默认 14 天内有互动的才列，阈值可调），半年不出现的人不该天天在 prompt 里站着。每人附一句关系与态度（取小传原文，不归类），聊天里 AI 的提及口吻才稳定。
- **按名字命中注入档案**：用户输入命中某好友名时（好友名不在 `identityNames()`，不会被检索误剥，bigram 可正常召回），向记忆区前置该好友的档案卡（性格/关系/口吻）+ 该好友相关的历史片段。复用检索的命中机制，不做第二套检索。
- **档案与记忆各司其职**：被问「小雨是谁」→ 档案卡回答性格与关系；被问「小雨上次说什么了」→ 片段回答事件。两者不互相覆盖，避免「记忆里的小雨和设定不是一个人」。

## 十一、分期建议

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 有人在 | `moments` 扩展 author、`friend_personas` 表、`friend_preferences` 偏好输入、花名册种子生成、好友错峰发帖 + UI 头像 + 状态区花名册行 + 管理最小集（改名/停用） | feed 里出现固定一小群人且符合偏好；AI 在聊天里提起的人与 feed 对得上 |
| P1 有人气 |好友评论（复用 service 范式，小传原文驱动）+ 管理完整集（换一个/删除/按偏好重建） | AI 与用户互动的动态下开始有人起哄；好友评论口吻一致；用户改偏好后可重建 |
| P2 有关系 | 互动写记忆 + 按名字命中注入档案 | 用户问「今天谁评论你了」AI 答得出；问「小雨是谁」人格回答稳定 |
| P3 能私聊 | `friend_threads` 表 +好友 system prompt 拼装 + 私聊页（复用聊天 UI）+ 巩固排除好友消息 + 信息隔离（弱痕迹机制） | 会话列表出现好友入口；和小雨私聊的内容不会串到主 AI 的记忆；「昨晚和小雨聊很久」成为可感知痕迹 |

## 十二、风险与边界

- **人格漂移**：每次好友生成必须带小传上下文，禁止无状态生成；口吻漂了就修小传里那一句，不换人设。
- **抢戏**：发帖频率、评论长度、每日总量三处默认值互相配合；上线后按 `logDebug("动态")` 的好友日志密度回调阈值。
- **冷启动**：花名册未生成前 feed 不渲染好友内容、AI 不提及不存在的朋友，形态与现状一致，向后兼容。
- **备份**：`backup.ts` 的导出/导入需覆盖 `friend_personas` 与新列。
- **不做**：好友群聊（好友间互相对话刷屏，稀释主角戏份）、好友主动私信（MVP）、好友单人动态写记忆（无互动价值且加速池子膨胀）、好友私聊内容注入主 AI 记忆区（破坏信息隔离的真实感）。
